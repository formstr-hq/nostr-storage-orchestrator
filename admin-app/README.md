# Storage Control

Standalone Tauri 2 administration client for the Nostr Storage Orchestrator. Android is the
primary target; Linux is supported from the same Vite/TypeScript and Rust codebase.

## Security model

- Profiles are stored in the WebView's app-local `localStorage`. The only persisted credential is
  the profile's NIP-49 `ncryptsec`; no plaintext Nostr secret key is accepted or stored.
- Passphrases exist transiently in the WebView form and Tauri IPC during unlock. They are never
  persisted or logged, and their Rust allocations are zeroized after use. Rust performs NIP-49
  work on a blocking worker so scrypt cannot freeze Android's UI thread.
- The decrypted `nostr::Keys` value is held only in Rust process memory for the active host. Lock,
  host switch, profile deletion, app exit, and page teardown remove it.
- Key generation, NIP-49, Bech32, event construction, and signing use pinned `nostr = 0.45.0`.
  Payload SHA-256 uses the maintained `bitcoin_hashes` library used internally by `nostr`.
  NIP-98 headers use `HttpData::to_authorization`; every POST signs the exact request body's
  payload hash.
- Imported NIP-49 credentials are limited to scrypt `log_n=16` (about 64 MiB), matching keys
  generated by the app, to avoid untrusted high-cost credentials exhausting a mobile process.
- Host URLs are normalized in Rust, require HTTPS, and reject credentials, query strings, and
  fragments. The Rust HTTP client refuses redirects so signed authorization cannot be replayed to
  a different URL.

The admin API contract used by this client is:

| Method | Path | Body |
|---|---|---|
| `GET` | `/v1/status` | none |
| `POST` | `/v1/invites` | `{}` |
| `POST` | `/v1/devices` | `{"npub":"npub1..."}` |

Every endpoint requires a strict `Authorization: Nostr ...` NIP-98 header. Status reads the
backend's sanitized top-level `peers` array and `connected_clients`; invite creation returns
`{ "invite": "..." }`.

## Linux prerequisites

Install Node.js 20 or newer, npm, Rust stable, and Tauri's Linux system packages. On Debian or
Ubuntu:

```bash
sudo apt update
sudo apt install -y libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev \
  libssl-dev libayatana-appindicator3-dev librsvg2-dev
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

On Arch Linux:

```bash
sudo pacman -Syu
sudo pacman -S --needed webkit2gtk-4.1 base-devel curl wget file openssl \
  appmenu-gtk-module libappindicator-gtk3 librsvg xdotool
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

Build and test from this directory:

```bash
npm install
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
cargo check --manifest-path src-tauri/Cargo.toml
npm run tauri:dev
npm run tauri:build
```

Linux bundles are written below `src-tauri/target/release/bundle/`.

## Android prerequisites

Install all of the following before initializing Android:

- Android Studio with the latest Android SDK Platform
- Android SDK Build-Tools, Platform-Tools, Command-line Tools (latest), NDK (Side by side), and CMake
- JDK 17 or JDK 21
- Rust Android targets

Set the environment (adjust the SDK and NDK paths to the installed versions):

```bash
export JAVA_HOME=/path/to/jdk-21
export ANDROID_HOME="$HOME/Android/Sdk"
export ANDROID_SDK_ROOT="$ANDROID_HOME"
export NDK_HOME="$ANDROID_HOME/ndk/<installed-ndk-version>"
export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin:$PATH"
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
```

Initialize once, then run or build:

```bash
npm install
npm run android:init
npm run android:dev
npm run android:build
```

`tauri android init` generates `src-tauri/gen/android`. Tauri's generated manifest includes
`android.permission.INTERNET`; verify it remains present at
`src-tauri/gen/android/app/src/main/AndroidManifest.xml` after regenerating. The committed Tauri
configuration sets Android min SDK 24, the app capability permits only core IPC for the main
window, and all network access is performed by Rust `reqwest` rather than the WebView.

For a physical device, enable USB debugging and confirm it appears in `adb devices` before
`npm run android:dev`. Release APK/AAB outputs are below
`src-tauri/gen/android/app/build/outputs/`; configure Android signing in the generated Gradle
project before distribution.
